The measured figures quoted below are offline results recorded in those docs, not guarantees. What a round is worth

One task, one presigned URL that lives 300 seconds, and no feedback afterwards. The reply to the validator is an empty acknowledgement. The dataset travels out of band as a PUT to S3, so a miner that misses the window is indistinguishable from one that was never contacted. 

final_score = total_weighted_score × consistency_factor × distribution_fidelity_factor

The three factors are multiplicative, so each one is a veto. A zero anywhere zeroes the round. Stages 1 and 2 run once and are seed independent; stages 3, 4 and 5 re-run for every round seed and the result is averaged.

The coverage cells

A cell is one combination of mutation, Cas system and strand. Two mutations, two Cas systems and two strands make eight cells, and the rows are distributed across them.

Stage 5 measures coverage as entropy over the declared support, and then takes a geometric mean of six ratios with every ratio floored at 1e-9. Those two rules punish very different mistakes, and the gap between them is large:

A ratio that genuinely reaches zero caps the factor at {{ flooredCeiling | number: '1.3-3' }}, the sixth root of the floor, however good the other five are. Only a collapsed dimension does that: every row on one Cas system, one strand or one mutation. An empty cell is a different thing and costs about two percent, because seven of eight cells still carry most of the joint entropy. Worth knowing when reading design.py, whose comments call a single empty cell the 1e-9 cliff.

Filling every cell is still the right rule. It is cheap, it keeps that two percent, and it rules out the collapse that does cost a round.

Collapsing each cell onto a single coordinate is the other half of the design. Every row in a cell then shares one stage 2 feature vector, so stage 4's forest sees eight groups instead of 250 noisy points.

Three pressures act on the split at once. Mutation weight pulls rows toward the higher-weighted mutation, coverage entropy pulls them level, and cut probability pulls them toward Cas9. The hill climb resolves all three together.

Accessibility and the cut probability Computed from the live cell-type table using stage 3's own formulas.

The contract's cell type is looked up in the accessibility table, and accessibility scales stage 3's energy, which in turn sets the cut probability: 

energy = clamp(0, 1, accessibility × (1.8·gc + 0.6·exp(−distance / 1500) + region_offset))
cut_probability = clamp(0.4, 0.99, base + 0.18 × energy)     base = 0.86 for Cas9, 0.78 for Cas12a

The table below substitutes the miner's own design: GC pinned to {{ gcAtOptimum * 100 }} percent and the nearest usable PAM, which puts the inner term at about 1.5 before accessibility scales it. Region offset is zero for every mutation region seen so far. Real per-row values move with the actual GC and distance, so read these as the best case for each cell type.

The offline harness runs the miner against a recorded task and scores it through the validator's own entry point, not a reimplementation. It reproduces the two asymmetries the live subnet has: the miner is run blind with the seed forced to 0, and the validator is given seeds the miner never saw.

Select a task by id prefix rather than list position for anything you want to repeat, because a fetch prepends newer rounds. Note also that total_weighted_score and distribution_fidelity_factor are identical on every seed, since neither reads one. All the variance is in consistency_factor, so a single-seed comparison between two designs is mostly noise.

The Tasks page runs the same harness. Its play button benchmarks one task and shows the result, which is the quickest way to see these numbers for a real contract.
